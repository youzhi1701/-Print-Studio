> 面向飞书多维表格的模板编辑、预览与批量打印工具，重点解决“选记录 → 选模板 → 编辑 → 预览 → 打印”的完整工作流。

## 项目概览

超级打印不是营销展示页，而是一套真正用于编辑与打印的业务工具。项目围绕“快速打印”和“模板设计器”两条主线展开，并通过统一渲染逻辑尽量保证编辑、预览和最终打印结果一致。

当前生产部署：

- Vercel Project：`super-print`
- Production Domain：`feishu-print-ashen.vercel.app`
- 数据来源：飞书多维表格 SDK
- 私人模板存储：Upstash Redis

## 核心能力

### v20261008-51 · 按表格名称自动匹配模板
- 进入或切换飞书数据表时，自动根据“表格名称”匹配模板名称
- 例如“物流面单”会优先匹配“物流面单 100×150”等同名/高相似模板
- 匹配会忽略尺寸、空格、符号、“模板/标签/单据”等附加词，避免名称稍有差异就失配
- 用户后续手动切换模板后，会记住“该飞书表格 → 该模板”的对应关系
- 下次进入同一张表优先使用用户手动选择，不再被自动匹配覆盖
- 不同飞书表格可以各自绑定不同模板，仍可随时从模板库重新调整

### v20261008-51 · 记录区域显示当前表格名称
- 快捷打印顶部“记录”区域的主标题改为当前飞书数据表名称，例如“盛世白银发货单”
- 不再用订单编号/序号/收件人冒充记录区域主标题
- 当前选中的具体记录改为副标题显示；未选记录时显示“未选择记录 · 点击选择”
- 表格名称进入 bridge 数据，设计器/子窗口后续可统一复用同一上下文

### v20261008-51 · Table Model V4
- 表头、数据行、手动行、汇总行统一进入同一张真实 HTML `table`，不再用“主体表格 + 特殊汇总区域”拼接
- 新增统一 `buildTableGrid()`：先完成可见列、行、合并、rowspan/colspan、行高计算，再交给 renderer
- renderer 退化为纯渲染层，恢复浏览器原生 `border-collapse: collapse`；真实 DOM 正确后由浏览器统一处理表格边线
- manual/summary 行属于真实 tbody 行，合并汇总只使用普通 `colspan`
- 用户手动调整某一行高度时，只将该行切换为 fixed，不再把整张表的自动行高一起关闭
- 右侧属性面板刷新和字段编辑不再偷偷重新执行智能列宽；只有明确点击“自动适配页面”时才重新计算智能列宽
- 表格视觉高度统一来自 canonical grid 的 totalHeight
- 列宽/行高拖动辅助层继续独立于真实 table border，编辑态不会改变打印边框

### v20261008-51 拖动辅助线与真实边框彻底分离
- 修复选中表格时列宽/行高拖动辅助线长期贯穿整张表，造成“内部多出一堆蓝线/假边框”的问题
- 列宽与行高仍保留大命中热区，拖动不变难
- 默认只显示短小蓝色抓手，不再绘制贯穿合并单元格的整条辅助线
- 只有鼠标悬停或正在拖动时，才显示完整蓝色定位线
- 表格选中外框改为外置虚线，与真实黑色表格边框拉开距离
- 单元格选中高亮进一步减弱，不再盖住真实边线
- v47 的单边界真实表格线继续保留，编辑辅助线不再参与表格结构视觉

### v20261008-51 表格边线统一重构
- 表格不再使用“table 外框 + 每个单元格四边框 + collapse”叠加方案
- 改为单边界模型：每条横线/竖线只绘制一次，避免重复线、粗细不一、交叉错乱
- 合并单元格自动抑制内部边界，汇总行与普通数据行使用同一套边线规则
- 外框由最外侧单元格共同闭合，不再额外叠一层 table border
- 编辑态单元格选中改为半透明内阴影，不覆盖真实打印边线
- 整张表选中仅保留独立蓝色外框，与真实表格线分离
- 编辑器、实际预览和打印继续共用同一套表格 HTML 渲染

### v20261008-51 表格交互优先级收口
- 不再让“整表拖动”直接抢占单元格的 pointerdown；表格表面改为独立手势状态机
- 单击正文单元格：选中单元格并稳定显示合并/拆分/加行/加列/删行/删列工具条
- 按住并移动超过 5px：才切换为整表拖动，避免轻点就误移动
- 单击表头：选中整列；拖动表头超过阈值：移动整表
- Shift + 单元格拖动：继续用于连续范围选择
- 列宽线、行高线、缩放手柄、工具条按钮优先级最高，不参与整表移动
- 用户主动新增的 manual row 继续保持可见，不再被空行隐藏逻辑过滤

### v20261008-51 加行显示修复
- 修复点击“加行”后模型已经插入空白行、但画布看不到新增行的问题
- 根因是新增行为 manual row，随后又被 `emptyBehavior=hide` 当作空数据行过滤掉
- 现在用户主动新增的空白行始终保留显示，直到用户自己删除
- 编辑器、实际预览与打印统一遵循同一行可见规则
- 保留整表任意区域拖动、列宽/行高拖动和单元格高级编辑

### v20261008-51 整表任意区域直接拖动
- 选中表格后，可直接在表头或正文任意单元格上按住拖动整个表格，不再必须抓边角/空白区域
- 普通拖动优先移动整张表；单击单元格仍可进入单元格选择
- Shift + 拖动单元格继续保留范围选择能力
- 列宽线、行高线、缩放手柄和表格工具条仍各自优先响应，不与整表拖动冲突
- 实际发生拖动后短暂抑制单元格 click，避免松手时误选单元格

### v20261008-51 空列状态与智能列宽统一
- 右侧列配置与画布使用同一套可见列判定，空字段会明确显示“当前为空 · 已隐藏”
- 隐藏空列后，仅对真实可见列重新归一化列宽，不再让隐藏列暗中占据空间
- 自动布局状态下，打开表格属性即重新应用智能列宽；用户手动拖过列宽后不强制覆盖
- 图片列采用紧凑宽度，数量/价格采用窄列，商品名称和长文本优先获得剩余空间
- 自动行高遇到图片时给出合理的最小图片行高，图片继续保持 contain
- 修改列绑定后立即重新计算该列是否可见，右侧状态和画布同步更新

### v20261008-51 空列状态与列宽统一
- 右侧列配置会明确标记因当前数据为空而隐藏的列：`当前为空 · 已隐藏`
- 空列隐藏后，画布可见列会重新归一化到 100% 宽度，不再留下“幽灵空白”
- 图片列采用紧凑宽度策略，默认约 18mm，不再吞掉大块横向空间
- 数量列默认约 12mm，价格列默认约 18mm；商品名称与商品属性获得主要剩余空间
- 智能适配时按“窄字段固定/紧凑 + 长文本弹性”重新分配列宽
- 保留空列配置本身，不删除用户设置；数据恢复后列会自动重新显示

### v20261008-51 绑定字段与显示内容同步切换
- 数据字段切换绑定字段时，如果当前显示内容仍属于默认模板，会自动同步为新字段的默认显示内容
- 例如 `电话：{{电话}}` 切换到“快递单号”后自动变为 `快递单号：{{快递单号}}`
- 兼容全角/半角冒号与可选空格的默认写法
- 用户已经自定义过的显示内容不会被覆盖
- 右侧显示内容、画布、保存数据、实际预览/打印继续使用同一份字段模板
- 保留数据字段默认居中、表格表头独立对齐、多选批量调整和属性输入焦点保护

### v20261008-51 前几轮问题合并收口
- 数据字段新建时默认 **居中对齐**
- 数据字段默认显示内容统一为 `字段名：{{字段名}}`，例如 `电话：{{电话}}`
- 自动绑定字段时也使用同一默认显示规则，不再退回成只有 `{{字段}}`
- 保留用户手动修改过的显示内容和对齐方式，不做强制覆盖
- 表格列配置继续保持“表头 / 字段 / 表头左中右对齐”，不恢复已删除的“内容”板块
- 多选批量调整继续支持字号、字重、加粗、文字对齐、统一尺寸及批量元素操作
- 属性输入焦点保护继续生效，避免输入一个字符后失焦

### v20261008-51 紧凑列配置

### v20261008-51 表格列配置精简

- 保留列拖动排序、删除、列宽拖动和高级单元格编辑

### v20261008-51 属性输入焦点保护
- 修复属性面板输入框“输入一个字符后就失去焦点”的问题
- 根因是自动保存后收到快捷页/桥接回传，旧逻辑会再次执行 `syncProps()`，从而重建右侧属性控件
- 用户正在属性面板输入时，只刷新画布，不重建右侧属性面板
- 结束输入后仍保持正常的数据同步、自动保存与画布更新

### 自动表格
- 每列支持“表头 + 绑定字段 + 自由内容模板”
- 表头默认跟随绑定字段标题，但用户手动修改后保持自定义内容

- 长文本自动估算行高
- 空列默认隐藏
- 页面尺寸变化时重新适配
- 用户手动修改后尊重人工布局，不反复强制重排

5. 云端同步后可跨设备继续使用

## 构建与发布

项目以静态前端 + Vercel Serverless API 方式部署。

生产环境至少需要：

```text
SESSION_SECRET
KV_REST_API_URL
KV_REST_API_TOKEN
```

同时兼容 Upstash 原生命名：

```text
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
```

`SESSION_SECRET` 仅用于服务端会话签名，不应提交到仓库。

正式版本统一在 GitHub Releases 中保留版本快照，生产站点继续由 Vercel 承担在线部署。

## 数据、安全与使用边界

- 飞书业务数据仅用于当前打印与模板渲染流程
- 私人模板按用户空间隔离
- Session 密钥与 Redis Token 不提交到 GitHub
- 手机号当前作为私人模板空间的身份入口，不等同于高安全等级身份认证
- 打印结果仍应在正式输出前通过成品预览复核
